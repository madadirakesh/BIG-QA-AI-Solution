## 2. Where things go (project layout)

Put new code in the right folder — this is the highest-value rule. Do not invent new folders.

| Path | What belongs here |
|------|-------------------|
| `test/features/*.feature` | Gherkin scenarios (one feature file per feature/page area) |
| `test/stepDefinitions/*.ts` | Step definitions — glue between Gherkin and Page Objects |
| `test/pageObjects/*.ts` | Page Objects — one class per page/component, each takes a `Page` |
| `test/hooks/hooks.ts` | `Before`/`After` browser lifecycle, `setDefaultTimeout`, screenshot on failure. **Owns the Page — rarely edit.** |
| `test/utils/configReader.ts` | Centralised `.env` access (`ConfigReader.getProperty`, `getEnvUrl`) |
| `test/utils/reports.ts` | Reporting helpers |
| `cucumber.js` | Cucumber.js config — glue/feature globs, ts-node. The single source of truth for how the suite loads. |
| `results/` | Timestamped reports + screenshots (generated at run time — never commit/edit) |
| `package.json`, `tsconfig.json` | Dependencies / TS config |

## 3. How to add a new test (canonical workflow)

1. **Write the scenario** in `test/features/*.feature` using Gherkin. Use only `Given` / `When` /
   `Then` step keywords (see §4). Tag smoke-critical scenarios with `@smoke`.
2. **Add/extend the Page Object** in `test/pageObjects/`. Put every selector here as a class
   field/constant — never inline a selector inside a step. Each Page Object takes a `Page`.
3. **Write the step definitions** in `test/stepDefinitions/`. Get the page from the Cucumber World
   (`this.page`) or `import { page } from "../hooks/hooks"`, instantiate the Page Object, and assert
   with `expect` from `@playwright/test`.
4. **Read inputs from config**: URL via `ConfigReader.getEnvUrl()`, credentials via
   `ConfigReader.getProperty("USER")` / `getProperty("PASSWORD")`. Never hard-code.
5. **Run it**: `npm test -- --tags "@smoke"` then `npm run report`.

### Reference patterns (copy this style)

Page Object — selectors as fields, `Page` injected via constructor:

```typescript
import { Page } from "@playwright/test";

export class LoginPage {
  private readonly usernameSelector = "#txtUserID";
  private readonly loginButtonSelector = "#sub";

  constructor(private page: Page) {}

  async open(appUrl: string) {
    await this.page.goto(appUrl);
  }

  async login(user: string, pass: string) {
    await this.page.locator(this.usernameSelector).fill(user);
  }
}
```

Step definition — typed against the custom World, page from `this`:

```typescript
import { Given } from "@cucumber/cucumber";
import { ICustomWorld } from "../hooks/hooks";
import { ConfigReader } from "../utils/configReader";
import { LoginPage } from "../pageObjects/LoginPage";

Given("I launch the application", async function (this: ICustomWorld) {
  const loginPage = new LoginPage(this.page!);
  await loginPage.open(ConfigReader.getEnvUrl());
});
```

## 4. Coding rules (do / don't)

**Locators & waits**
- Selectors are Playwright strings (CSS, `text=`, role). Playwright **auto-waits** for
  actionability — **do not** use fixed sleeps. Use `await page.waitForLoadState()` /
  `locator.waitFor()` when an explicit wait is genuinely needed.
- All Playwright calls are async — always `await` them.
- Use **real, unique** selectors for the actual app — do not hallucinate selectors/URLs. The
  shipped sample uses lenient comma-separated fallback selectors; replace with the real ones.

**Cucumber / Gherkin**
- Step functions use `Given`, `When`, `Then` (from `@cucumber/cucumber`). In `.feature` files use
  `Given` / `When` / `Then`.
- **Never** use `And` / `But` as a step keyword in code — Cucumber matches on step **text**, so a
  Gherkin `And ...` line is matched by the preceding `Given`/`When`/`Then` registration.
- Type step callbacks as `function (this: ICustomWorld)` so `this.page` is available and typed.

**Structure**
- One Page Object per page/component, each taking a `Page`. The browser/`Page` is owned by
  `test/hooks/hooks.ts` — get it from the World (`this.page`) or the module `page` export; never
  launch a browser in steps or pages.
- Read all config through `ConfigReader` — never read `process.env` directly elsewhere.

## 6. Credentials & secrets (do not "fix" this)

In `.env`:
- `APP_URL`, `USER` — plaintext, safe to edit.
- `PASSWORD` — stored as **`ENC:<token>`** (AES-256-GCM). `ConfigReader` decrypts it at run time
  using `CRED_KEY`, so `ConfigReader.getProperty("PASSWORD")` returns plaintext. **Do not** replace
  the `ENC:` value with a plaintext password, and **do not** delete or regenerate `CRED_KEY` —
  either breaks decryption.
- Never hard-code credentials in feature, step, or page files. Never commit real secrets (`.env`
  is gitignored).

## 7. Quick "don't" checklist

- ❌ Selectors inside step files → ✅ fields/constants in the Page Object.
- ❌ Launching a browser in a step → ✅ use `this.page` from the World / hooks.
- ❌ Missing `await` on a Playwright call → ✅ always `await`.
- ❌ `And` / `But` step keyword in code → ✅ `Given` / `When` / `Then`.
- ❌ Plaintext password in `.env` → ✅ keep the `ENC:` token + `CRED_KEY`.
- ❌ New top-level folders → ✅ use the layout in §2.
